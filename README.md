# 대구 통합돌봄네트워크 ON

운영: https://daegu-care.oconia.co.kr/ · GitHub Pages `main /docs`

`src/app.js`와 `src/styles.css`가 서비스 원본이며, `docs`는 배포 결과물이다. 기존 브라우저 데이터 키와 회원사 ID를 유지한다. 개인 후원 내역·관리 화면·로컬 등록 항목에는 공개 공유 주소를 만들지 않는다.

## SNS 썸네일

독립된 공유 콘텐츠는 `src/social-covers.json`에 개별 제목, 사진, 출처를 가진다. 같은 실제 사례를 다루는 소식·사진·지난 일정은 하나의 소식 주소로 공유한다. 공개 화면과 원본 사진 다운로드는 유지하며, 공유 주소와 검색 메타데이터만 같은 사례에 연결한다. 현재 공개 화면 68개 중 같은 사례를 다루는 10개 화면을 연결하여 독립 공유 콘텐츠는 58개다. 9개 채널의 표지는 총 522장이다. 검수표의 개수는 실제 생성된 목록에서 계산한다.

서로 다른 콘텐츠에는 서로 다른 원본 사진을 배정한다. 같은 사진의 파일명·해상도·크롭·문구만 바꾸어 별개의 사진으로 세지 않는다. 사진을 원래 사례와 다른 사건의 현장 사진처럼 표시하지 않는다. 원본과 완성 이미지의 해시 및 이미지 유사도를 검사한다. 같은 콘텐츠의 SNS 규격 변환은 해당 사례의 일관성을 유지하되, 동일 규격인 네이버·밴드도 별도 구도로 구성한다.

실사진을 배경으로 핵심 제목을 크게 표시하며, AI 이미지나 단색 로고 이미지를 공유 썸네일로 사용하지 않는다. 다른 지역·기관의 사진을 참고할 때는 이미지와 공유 창에 그 맥락과 사진 기관을 표시한다. 특정 행사의 현장 사진을 확보하지 못한 기록은 표지에 ‘자료로 읽는’을 크게 표시하고 관련 실제 사례 사진임을 밝힌다. 변경 금지 사진은 가공하지 않는다. 기관 자체 사진을 확보하면 해당 기관의 사진으로 교체한다. 추가 원본과 출처는 `src/social-photos.json`에서 관리하며, 본문 사진의 교정은 `src/content-photos.json`에서 관리한다. 사진을 추가해도 공개 콘텐츠 수가 자동으로 늘어나지 않는다.

공통·카카오톡·링크드인·X·네이버·밴드·인스타그램 피드·스토리/릴스·유튜브의 9가지 규격을 생성한다. 채널별 이미지는 각 콘텐츠의 공유 창에서 저장할 수 있다. 공개 콘텐츠에는 해시 없는 HTML 주소와 정적인 OG/Twitter 메타 태그를 제공한다. 카카오톡·링크드인·X에는 해당 규격 이미지를 담은 별도 공유 페이지도 제공한다. 인스타그램과 유튜브는 저장한 JPG를 게시물 작성 시 첨부한다.

공유 아이콘의 기본·호버·누름 배경은 항상 투명하게 유지하고 터치 영역과 키보드 초점 표시는 보존한다.

## 확정 기관 정보의 확인 범위

사용자가 제공한 동의기관 PDF를 기준으로 확정 기관 7곳을 반영한다. 이 중 대구도우누리·위드의료복지사회적협동조합·대구돌봄사회적협동조합·내일앤사회적협동조합·모두행복센터 5곳은 공식 사이트 또는 블로그의 주요 원문 내용을 확인했다. 우리함께통합돌봄사회적협동조합은 제공 자료에 홈페이지가 없다. 사회복지디자인연구소사회적협동조합의 다음 카페는 접근이 차단되어 원문을 확인하지 못했다. 별도로 검색해 공익활동지원센터에 기관이 직접 작성한 워크숍 후기를 확인했고, 우리함께의 관련 네트워크 행사 사진도 확인했다. 기관의 자체 서비스 현장과 관련 네트워크 활동을 구별하며, 7곳의 모든 사이트를 열람했다고 주장하지 않는다.

확정 기관 7곳의 목록 카드는 실제 사진을 표시한다. 대구도우누리는 수성구청의 영양식 기탁 사진, 사회복지디자인연구소는 조합원 워크숍 사진, 내일앤은 더봄 나눔 사진으로 연결한다. 우리함께는 관련 네트워크 발대식 사진임을 명시한다. 화면 사진은 SNS 표지의 존재 여부와 분리해 관리하며, 빈 카드가 다시 생기지 않는지 검사한다. 새로 발굴한 활동 소식과 원문은 `src/researched-news.json`에 보관한다. 작은 화면용 사진은 원본과 구별해 생성하고 원본 파일도 유지한다.

## 빌드와 검증

Node.js와 Pillow가 설치된 Python을 사용한다. Codex의 번들 런타임에도 포함되어 있다.

```text
node scripts/social-catalog.cjs
python scripts/sanitize-photo-metadata.py
python scripts/verify-unique.py --source-only
python scripts/render-social.py
node scripts/build.cjs
node scripts/verify-social.cjs
python scripts/verify-images.py
python scripts/verify-unique.py
python scripts/contact-sheets.py
node scripts/preview.cjs
```

새 콘텐츠 추가 시 `src/social-covers.json`에 제목과 실사진을 먼저 등록한다. 같은 사례의 다른 화면이면 기존 소식의 공유 연결을 사용한다. 사진 원본은 `docs/media`에 보관하고 `src/social-photos.json`에 출처와 이용 조건을 등록한다. 숨은 위치정보는 사진 픽셀을 보존하면서 제거한다. 새 이미지를 생성한 뒤 빌드·검증한다. 원본 중복이나 미검수 변경, 동일 썸네일은 빌드에서 차단한다. 점검 결과와 9개 채널 전체 비교 이미지·검수표는 `output/verification/social`에 저장한다. 검수표는 독립 공유 콘텐츠별로 표지를 보여주고, 같은 사례로 연결되는 사진·일정 화면을 별도로 나열한다.

공유 플랫폼이 이전 미리보기를 캐시할 수 있으므로 새 썸네일에는 내용에 따른 파일명을 사용하며, 공유 창의 링크도 해당 이미지 버전의 공개 페이지로 연결한다. 기존 공개 주소와 공유 주소는 유지한다. 이미 전송된 SNS 메시지의 캐시 교체와 실제 SNS 게시물 업로드는 별도의 플랫폼 작업이다.
