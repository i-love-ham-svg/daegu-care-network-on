# 대구 통합돌봄네트워크 ON

운영: https://daegu-care.oconia.co.kr/ · GitHub Pages `main /docs`

`src/app.js`와 `src/styles.css`가 서비스 원본이며, `docs`는 배포 결과물이다. 기존 브라우저 데이터 키와 회원사 ID를 유지한다. 개인 후원 내역·관리 화면·로컬 등록 항목에는 공개 공유 주소를 만들지 않는다.

## SNS 썸네일

독립된 공유 콘텐츠는 `src/social-covers.json`에 개별 제목, 사진, 출처를 가진다. 같은 실제 사례를 다루는 소식·사진·지난 일정은 하나의 소식 주소로 공유한다. 공개 화면과 원본 사진 다운로드는 유지하며, 공유 주소와 검색 메타데이터만 같은 사례에 연결한다. 오픈 전 전체 콘텐츠 검수 후 현재 공개 화면 77개 중 같은 사례를 다루는 10개 화면을 연결하여 독립 공유 콘텐츠는 67개다. 9개 채널의 표지는 총 603장이다. 검수표의 개수는 실제 생성된 목록에서 계산한다.

서로 다른 콘텐츠에는 서로 다른 원본 사진을 배정한다. 같은 사진의 파일명·해상도·크롭·문구만 바꾸어 별개의 사진으로 세지 않는다. 사진을 원래 사례와 다른 사건의 현장 사진처럼 표시하지 않는다. 원본과 완성 이미지의 해시 및 이미지 유사도를 검사한다. 같은 콘텐츠의 SNS 규격 변환은 해당 사례의 일관성을 유지하되, 동일 규격인 네이버·밴드도 별도 구도로 구성한다.

실사진을 배경으로 핵심 제목을 크게 표시하며, AI 이미지나 단색 로고 이미지를 공유 썸네일로 사용하지 않는다. 다른 지역·기관의 사진을 참고할 때는 이미지와 공유 창에 그 맥락과 사진 기관을 표시한다. 특정 행사의 현장 사진을 확보하지 못한 기록은 표지에 ‘자료로 읽는’을 크게 표시하고 관련 실제 사례 사진임을 밝힌다. 변경 금지 사진은 가공하지 않는다. 기관 자체 사진을 확보하면 해당 기관의 사진으로 교체한다. 추가 원본과 출처는 `src/social-photos.json`에서 관리하며, 본문 사진의 교정은 `src/content-photos.json`에서 관리한다. 사진을 추가해도 공개 콘텐츠 수가 자동으로 늘어나지 않는다.

2026.11.20 사용자 지시: 새 썸네일은 실제 사진 한 장이 전체 영역을 채우고 그 위에 문구를 올린다. 사진을 작은 박스로 넣거나 별도 패널에 담지 않으며, 흐리게 복제한 배경 위에 사진을 다시 넣는 구성을 사용하지 않는다. 얼굴·활동 위치에 따라 사진 초점과 제목의 위·아래 배치를 조정한다.

공통·카카오톡·링크드인·X·네이버·밴드·인스타그램 피드·스토리/릴스·유튜브의 9가지 규격을 생성한다. 채널별 이미지는 각 콘텐츠의 공유 창에서 저장할 수 있다. 공개 콘텐츠에는 해시 없는 HTML 주소와 정적인 OG/Twitter 메타 태그를 제공한다. 카카오톡·링크드인·X에는 해당 규격 이미지를 담은 별도 공유 페이지도 제공한다. 인스타그램과 유튜브는 저장한 JPG를 게시물 작성 시 첨부한다.

공유 아이콘의 기본·호버·누름 배경은 항상 투명하게 유지하고 터치 영역과 키보드 초점 표시는 보존한다.

## 확정 기관 정보의 확인 범위

사용자가 제공한 동의기관 PDF를 기준으로 확정 기관 7곳을 반영한다. 이 중 대구도우누리·위드의료복지사회적협동조합·대구돌봄사회적협동조합·내일앤사회적협동조합·모두행복센터 5곳은 공식 사이트 또는 블로그의 주요 원문 내용을 확인했다. 우리함께통합돌봄사회적협동조합은 제공 자료에 홈페이지가 없다. 사회복지디자인연구소사회적협동조합의 다음 카페는 접근이 차단되어 원문을 확인하지 못했다. 추가 검색으로 SDL 공식 블로그와 공익활동지원센터 참여후기를 확인했고, 우리함께 창립총회의 자체 사진과 원문도 확인했다. 네이버와 Google에서 7개 기관의 실제 검색 결과를 각각 확인했다. Google의 단순 HTTP 요청 실패와 실제 브라우저 결과 확인은 조사 기록에서 구별한다. 기관의 자체 서비스 현장과 관련 네트워크 활동을 구별하며, 7곳의 모든 사이트를 열람했다고 주장하지 않는다.

확정 기관 7곳의 목록 카드는 실제 사진을 표시한다. 대구도우누리는 수성구청의 영양식 기탁 사진, 사회복지디자인연구소는 조합원 워크숍 사진, 내일앤은 더봄 나눔 사진으로 연결한다. 우리함께는 기관명과 날짜가 확인되는 창립총회 자체 사진을 사용한다. 화면 사진은 SNS 표지의 존재 여부와 분리해 관리하며, 빈 카드가 다시 생기지 않는지 검사한다. 새로 발굴한 활동 소식과 원문은 `src/researched-news.json`에 보관한다. 작은 화면용 사진은 원본과 구별해 생성하고 원본 파일도 유지한다.

## 빌드와 검증

Node.js와 Pillow가 설치된 Python을 사용한다. Codex의 번들 런타임에도 포함되어 있다.

```text
node scripts/social-catalog.cjs
python scripts/sanitize-photo-metadata.py
python scripts/verify-unique.py --source-only
python scripts/render-social.py
node scripts/build.cjs
node scripts/verify-social.cjs
node scripts/verify-giving.cjs
node scripts/verify-sharing.cjs
node scripts/verify-content.cjs
python scripts/verify-images.py
python scripts/verify-unique.py
python scripts/contact-sheets.py
node scripts/preview.cjs
```

새 콘텐츠 추가 시 `src/social-covers.json`에 제목과 실사진을 먼저 등록한다. 같은 사례의 다른 화면이면 기존 소식의 공유 연결을 사용한다. 사진 원본은 `docs/media`에 보관하고 `src/social-photos.json`에 출처와 이용 조건을 등록한다. 숨은 위치정보는 사진 픽셀을 보존하면서 제거한다. 새 이미지를 생성한 뒤 빌드·검증한다. 원본 중복이나 미검수 변경, 동일 썸네일은 빌드에서 차단한다. 점검 결과와 9개 채널 전체 비교 이미지·검수표는 `output/verification/social`에 저장한다. 검수표는 독립 공유 콘텐츠별로 표지를 보여주고, 같은 사례로 연결되는 사진·일정 화면을 별도로 나열한다.

공유 플랫폼이 이전 미리보기를 캐시할 수 있으므로 새 썸네일에는 내용에 따른 파일명을 사용하며, 공유 창의 링크도 해당 이미지 버전의 공개 페이지로 연결한다. 기존 공개 주소와 공유 주소는 유지한다. 이미 전송된 SNS 메시지의 캐시 교체와 실제 SNS 게시물 업로드는 별도의 플랫폼 작업이다.

공유 아이콘은 클릭 즉시 시스템 앱 선택창을 호출하고 해당 콘텐츠의 제목과 공개 URL을 전달한다. 사진 파일을 함께 첨부하면 일부 앱에서 링크를 버리고 사진 메시지만 보내므로 기본 공유에는 files를 넣지 않는다. 수신 앱은 공개 페이지의 og:image·og:title·og:description으로 클릭 가능한 썸네일 링크 카드를 구성한다. 클릭 처리 중에는 다운로드나 별도 설정창을 기다리지 않는다. 취소하면 원래 화면을 유지하며, 시스템 공유 미지원·차단 환경에는 웹 공유와 링크 복사를 제공한다. 이미지 자체 다운로드는 대체 메뉴의 ‘이미지 저장’에서만 제공한다.

## 대표 서비스 공유

헤더의 ‘서비스 공유하기’는 개별 기관·소식 공유와 구별한다. 참여기관의 실제 공개 사진 위에 ‘돌봄이 필요한 순간, 우리 동네가 함께합니다’라는 서비스 가치 문구를 표시한다. 대표·기관·소식·정책·자료 등 모든 SNS 표지는 실제 사진 한 장이 전체 배경을 채우고 그 위에 제목을 배치한다. 작은 사진 패널이나 흐리게 복제한 배경을 사용하지 않는다. 개별 콘텐츠의 제목을 대표 서비스 문구로 대신 사용하지 않는다.

정사각·세로 표지만 수정할 때는 `python scripts/render-social.py --channels naver,band,instagram-feed,instagram-story`로 다른 채널의 공개 이미지 주소를 보존할 수 있다. 원본 사진·설명 변경이 있으면 해당 채널을 포함해 재생성한다. 채널별 인물 구도와 제목 위치는 `src/social-covers.json`의 `channelLayouts`에서 지정한다.

전달용 제안서는 `scripts/build-proposal.py`로 생성하며, 운영안 화면의 ‘제안서 PDF’에서 배포본을 내려받는다. 생성 후 모든 페이지를 렌더링해 한글·사진·링크·페이지 배치를 확인한다.

전체 이용자가 같은 서버 카운터를 사용한다. 새 대표 링크 1~10개에 같은 사진을 배정하고 11번째부터 다음 사진으로 바꾼다. 최신 공개 사진 10장 중 아직 사용하지 않은 사진을 먼저 선택하고, 새 사진이 없으면 기존 사진을 오래 사용하지 않은 순서로 순환한다. 원본 픽셀·원본 주소가 같은 사진은 한 장으로 센다. 이미 배정된 링크는 이후 사진·문구가 갱신되어도 원래 표지를 유지한다.

`node scripts/build.cjs`는 공개 사진·날짜·가치 문구의 변경을 감지해 대표 표지와 `docs/service-share-catalog.json`을 자동 갱신한다. 새 사진 피드는 `src/service-share-values.json`의 `feedFile`로 연결할 수 있으며, 공개 파일과 확인된 소속·사용 가능 상태를 가진 사진만 받는다. 확인되지 않은 날짜를 생성 시각으로 꾸미지 않는다. Python/Pillow가 필요한 변경은 `DAEGU_CARE_PYTHON` 또는 설치된 Python을 사용한다. 공유 서버는 60초 간격으로 마지막 정상 공개 목록을 갱신한다.

공유 카운터와 링크별 OG 페이지는 기존 오코니아 공용서버의 `/share/daegu-care/` 및 `/api/daegu-care/`에 분리되어 있다. `service-share-backend`는 이 기능의 모듈·스키마·실제 SQLite 테스트 원본이다. 별도의 `daegu_share_` 테이블만 사용하여 기존 서비스의 기록을 보존한다. 공개 링크는 서비스 가치 표지를 제공한 뒤 대구 통합돌봄 ON으로 이동한다. 계수는 고유 대표 링크 배정 수이며, 같은 URL의 재조회·미리보기·재등록은 중복 집계하지 않는다. 외부 앱의 실제 전송·재전달 성공 통계로 표시하지 않는다.

## 오픈 전 콘텐츠 검수

예시 기관 명의의 n1~n8과 행사 예시 e1/e2를 실제 기관의 공개 기록으로 전환했다. 추가로 기관 활동 9건을 등록했다. src/release-content.json은 검증된 소식·행사와 기관별 추가 정보를, src/institution-research.json은 검색 경로·출처·제외 근거를 보관한다. 사례의 개최일과 원문 게시일을 구별하고, 확인된 게시일만 Article.datePublished에 사용한다.

기관별 현장 갤러리는 사진의 실제 소속 기관을 검사하며 파일 기준으로 중복을 제거한다. 정책 6건과 자료 3건의 본문·검색 이미지·SNS 표지는 동일한 실제 사진을 사용한다. 외부 지역의 사례는 큰 문구로 구별한다. 확인받지 않은 예시 모금 누적액과 건수는 0에서 시작하며 브라우저에 저장된 후원 시연 내역은 보존한다.

SNS 로그인과 결제는 현재 시연 기능이다. 콘텐츠 검수 통과를 실제 인증·결제 연동 완료 또는 전체 서비스의 정식 오픈 승인으로 표시하지 않는다.

## 반응형 메뉴 검수

PC와 모바일·폴더블의 주 메뉴는 같은 `navs` 목록을 사용한다. 메뉴를 열면 첫 링크로 초점을 이동하고, Escape로 닫으면 메뉴 버튼으로 돌아간다. 950px 경계를 통과할 때 열림 상태를 초기화해 접기·펼치기나 창 크기 변경 후 메뉴가 저절로 다시 열리지 않게 한다. 높이가 낮은 화면에서는 메뉴 내부를 스크롤한다.

`node scripts/verify-navigation.cjs`는 실제 앱 함수와 클릭·키보드·미디어 변경 이벤트를 실행해 메뉴 초점, 닫기, 화면 폭 전환과 6개 공개 경로를 검사한다. 브라우저 화면 배치 검수는 별도로 수행하며 Chrome 화면 크기 미리보기를 실물 기기·접힘 센서·iOS 키보드 검수로 표시하지 않는다.
